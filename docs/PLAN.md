# 旧 Android 手机桌面状态屏：项目计划

日期：2026-10-09

状态：开发前方案；项目名称待定

## 1. 目标与使用流程

构建一个开源、本地优先的项目，将闲置 Android 手机变成桌面信息屏。Mac App 管理 Todo、插件、Agent 会话和显示设备；手机持续展示 Agent 状态与今日 Todo。未来通过插件扩展天气、股票等信息。

首个完整流程：安装 Mac App → 启用插件 → 配置 Agent 接入 → 添加 Todo → 手机配对 → 选择布局 → 实时显示。

成功标准：用户能看一眼手机就知道哪些 Agent 在工作、哪些需要处理，以及今天还剩哪些待办。

## 2. 第一版范围

### 必须交付

- Mac App：Todo 创建、编辑、排序、完成；插件启停与配置；设备配对与撤销；显示布局配置。
- Agent 插件：Claude Code、Codex CLI、pi 多会话监控，展示项目、状态、最近活动和更新时间。Codex 桌面端支持单独验证，未通过时明确标注不支持。
- 手机显示端：Agent 状态卡和 Todo 列表，横竖屏适配、连接状态、断线重连、适合远距离查看的字号。
- 插件 SDK：版本化协议、示例插件、配置声明、卡片数据校验、生命周期与故障处理。
- 本地持久化、可安装构建、开源说明及接入文档。

### 后续版本

- 天气、股票、日历等插件。
- 自定义卡片渲染器、趋势图、多屏轮播、跨平台桌面端。
- 插件目录和安装更新机制。

第一版不包含手机审批 Agent 操作、启动编程任务、云账号或跨互联网同步。手机首先承担显示职责，Todo 在 Mac 管理。

## 3. 架构

```text
Agent Hooks / pi 扩展     外部数据源（天气、股票等）
           ↓                        ↓
       Agent 插件              其他数据插件
           └──────────┬─────────────┘
                     ↓ 版本化消息协议
                 Mac 核心服务
       ┌─────────────┼──────────────┐
       ↓             ↓              ↓
   插件运行管理   本地存储/配置    卡片与布局服务
       └─────────────┼──────────────┘
                     ├─ Mac App 管理界面
                     └─ 配对后的局域网连接
                                   ↓
                          Android 显示客户端
```

核心服务是数据与配置的唯一管理入口。手机保存必要缓存，重连时先获取完整快照，再接收增量更新。

### 推荐技术路线（开发初期验证后确定）

- Mac App：优先评估 SwiftUI + AppKit，适配菜单栏、后台运行及原生配置界面。
- 核心：独立于界面的 Swift 模块，本地数据库采用 SQLite。
- 插件：独立进程，第一方和第三方使用同一协议；示例 SDK 优先 TypeScript，协议允许其他语言实现。
- 本地插件 IPC：以带明确边界的 JSON 消息实现。插件 stdout 专供协议，stderr 专供日志；Agent Hooks 的接收可使用 Unix Socket。
- 手机同步：完整快照 + 增量事件，优先评估 WebSocket；带协议版本和序号。
- Android：先验证浏览器显示方案。若旧设备浏览器无法满足常亮、全屏、重连或安全配对要求，则采用轻量 Android App；WebView 是否可用也必须实测。

独立插件进程不等于权限沙箱。第一版权限声明用于用户知情与核心 API 授权，不能宣称可以阻止插件直接访问操作系统资源。第三方插件仅在用户明确安装并启用后运行。

## 4. 插件模型

### 插件描述文件

包含 `id`、`name`、`version`、`apiVersion`、`entrypoint`、支持的卡片类型、配置 schema、权限声明和调度需求。插件 ID 与卡片 ID 稳定且唯一。

### 协议能力

- 握手：协商 API 版本与能力，不兼容插件给出可读提示。
- 生命周期：初始化、启动、停止、配置变化、健康检查。
- 配置：核心提供持久化配置；凭据由 Mac 钥匙串保存，仅按需要交给插件。
- 数据：插件发布完整卡片数据或受约束的更新；核心验证后同步。
- 操作：卡片可以声明操作，核心按操作 ID 路由回插件。第一版操作发生在 Mac 端。
- 调度：支持事件驱动和定时刷新；提供超时、退避和刷新频率限制。
- 故障：区分插件进程故障、数据获取失败和数据过期；保留最后成功数据及时间。

核心提供命名空间存储、配置、调度、日志和卡片发布接口。插件不能直接修改其他插件的数据。

### 第一版卡片

| 类型 | 内容 | 首批用途 |
| --- | --- | --- |
| 状态卡 | 标题、状态、摘要、时间 | Agent 会话 |
| 列表卡 | 列表项、完成状态、进度 | Todo |
| 指标卡 | 数值、单位、变化、更新时间 | 示例插件；未来天气/股票 |
| 文本卡 | 标题与有限长度文本 | 提醒或示例 |

插件负责语义数据，客户端统一负责字体、色彩、布局和主题。第一版不接收任意 HTML、JavaScript 或插件自定义 UI 代码。

### 插件与布局的关系

一个插件可生成多张卡片。布局按设备保存，包含卡片选择、顺序、占用空间与显示选项。动态 Agent 会话通过固定的“Agent 区域”加入布局，无需用户逐一摆放；等待处理的会话优先展示。

## 5. Agent 状态插件

参考项目：

- [itdragons/open-vibe-island](https://github.com/itdragons/open-vibe-island)
- [Hooks 文档](https://github.com/itdragons/open-vibe-island/blob/main/docs/hooks.md)
- [发布说明](https://github.com/itdragons/open-vibe-island/releases)

已从文档确认的路径：Claude Code 与 Codex CLI 使用 Hooks；pi 使用 TypeScript 扩展；本地事件进入桥接与会话状态模型。实际支持范围以安装版本和端到端测试为准。

### 实施规则

- 先检查发布 tag 与 main 的差异，固定参考 commit，阅读适配器、状态转换、安装器及相关测试。
- 使用事件更新状态，本地会话文件用于发现和恢复，进程或心跳用于判断存活。三种信息不能互相混淆。
- 使用工具类型 + 会话 ID 标识会话，不能仅按项目目录合并。
- 状态包含：空闲、工作中、等待处理、本轮完成、异常、状态未知。会话存活状态单独记录。
- 本轮完成不自动完成 Todo；单次工具失败也不直接等于整个任务失败。
- 使用轮次/事件标识与时间处理重复、延迟和过期事件，避免上一轮的 Stop 覆盖新一轮状态。
- 状态收集采用观察方式，短超时、失败放行，不接管原工具的审批流程。
- Hook 安装合并用户现有配置，记录自身条目；卸载只移除自身条目。
- pi 心跳只刷新存活时间，不能将已完成会话重新标为工作中。
- Codex 桌面端必须验证能否观察其他已有会话；启动一个 app-server 进程本身不能作为验证结果。

复用代码前核对仓库 LICENSE 与文件许可。若选择基于其源码派生，则围绕 GPL v3 规划发布并保留来源；仅借鉴机制的独立实现单独选择许可。此决定在编写复用代码前完成。

## 6. Todo 插件

Todo 通过插件接口实现，不在核心中添加专属业务逻辑。

首版字段：ID、标题、备注、状态、排序、计划日期、创建/修改时间、可选的关联 Agent 会话 ID。

Mac 管理操作：新增、编辑、完成/恢复、排序、删除。手机展示今日待办、进行中项目及完成进度。计划日期遵循 Mac 配置的时区；关联会话失效时 Todo 仍可使用。

## 7. 设备连接与旧手机适配

- 初次连接通过二维码或配对码建立设备身份，支持设备列表与撤销配对。
- 配对凭据设置有效期，不在普通日志中打印；局域网接口不能默认向所有访问者提供数据。
- 数据仅同步展示必需字段，API 密钥保留在 Mac。
- 联网方案同时验证身份校验与传输保护，不因选择浏览器方案而跳过这一步。
- 连接状态与 Agent 状态分开呈现：Mac 离线时保留缓存并显示“最后更新于”。
- 重连后先同步快照，序号缺失时重新同步，不能依赖完整接收所有增量。
- 在真实旧手机验证系统版本、浏览器/WebView、常亮、横竖屏、中文字体、低内存和长时间运行。
- 减少持续动画，避免高频刷新；提供暗色主题、字号和亮度使用建议。

## 8. 开发阶段与验收

按完成标准推进，暂不给出日历工期。

| 阶段 | 工作 | 验收标准 |
| --- | --- | --- |
| P0 技术验证 | 审阅参考源码；确定许可路线；验证三种 Agent 的事件；验证旧手机显示与配对方案 | 形成支持矩阵、事件样本和技术决定，确认关键路径可行 |
| P1 核心与插件骨架 | 建立协议、插件运行器、存储、配置、日志；实现示例插件 | 不修改核心即可加载示例插件；崩溃与版本不兼容有明确处理 |
| P2 显示链路 | Mac 服务、手机配对、快照/增量同步、卡片渲染、布局 | 两台设备可以选择不同卡片；断线重连后内容正确 |
| P3 Todo 插件 | Mac 管理界面与手机展示 | 重启后数据保留；操作实时同步；日期与顺序正确 |
| P4 Agent 插件 | 按 Claude Code → pi → Codex CLI 接入；单独验证桌面端 | 多会话状态正确；等待处理可见；异常退出不会无限显示工作中 |
| P5 发布准备 | 整体体验、长时间运行、安装与卸载、SDK 示例、开源文档 | 新用户可按文档完成安装和配对；支持范围与限制明确 |

P2 可使用模拟数据推进，但发布前 P4 必须通过真实工具验证。P0 若发现手机浏览器能力不足，及时调整客户端路线。

## 9. 验证重点

- 协议测试：不兼容版本、错误数据、重复消息、过大消息、超时和进程退出。
- 状态转换测试：等待审批后继续、轮次交错、工具失败后继续、正常结束、异常退出、心跳超时。
- 同步测试：Mac/手机重启、Wi-Fi 中断、快照与增量衔接、设备撤销。
- 数据测试：Todo 持久化、插件配置更新、数据库迁移。
- 真实设备检查：至少一台目标旧 Android 手机与开发 Mac，持续运行一个工作日，记录内存、CPU、断线恢复和状态延迟。
- Hook 安装/卸载：保留现有用户配置，采集服务关闭时不妨碍 Agent 运行。
- 扩展性验收：新增指标示例插件，仅使用公开 SDK 即可在现有手机端显示；不修改核心业务代码。

- 插件 SDK：协议文档、示例插件、配置示例、开发与调试指引。

## 11. 开发前待确认/实测

1. 目标旧手机型号、Android 版本与浏览器版本。
2. Mac 系统版本，Claude Code、Codex、pi 的实际使用入口和版本。
3. 选择基于 Open Island 派生，还是独立实现并借鉴其接入方式。
4. 浏览器显示能否满足实际设备的常亮和安全连接要求。

这些问题优先在 P0 解决；Todo、插件协议和卡片模型可以先行设计。
